ЛЕКЦИЯ 4: SPRITE ANIMATION AND EFFECTS
1. Анимация состоит из кадров и времени. 6–12 FPS для пиксельной анимации, пример 4 кадра / 8 FPS. Частота анимации отличается от частоты отрисовки игры.
2. Sprite Sheet содержит картинки, Animation Clip задаёт кадры и Samples, Animator выбирает состояние по параметрам.
3. Импорт учебных листов: Multiple, PPU 128, Point, Compression None. Slice: Grid By Cell Size 128×128, затем Apply. Размер относится к учебным спрайтам.
4. Перетаскивание всех кадров создаёт клип и Animator. Animation открывается Ctrl+6. Samples 8, Loop Time включён. Idle, Walk, Jump — отдельные клипы.
5. Animator: Idle по умолчанию, Walk зациклен. Speed > 0.01 переводит в Walk, Speed < 0.01 возвращает Idle. Для реакции на ввод Has Exit Time выключен.
6. Компоненты кэшируются GetComponent<Animator>() и GetComponent<SpriteRenderer>(). Код передаёт anim.SetFloat("Speed", Mathf.Abs(x)), sr.flipX = x < 0 при x != 0, anim.SetBool("Grounded", grounded).
7. Монета: 6 кадров / 10 FPS. Огонь: 6 кадров / 11 FPS. Для зацикленной среды не нужны отдельные скрипты и переходы Animator.
8. Particle System: Lifetime 0.6, Speed 2, Cone 8°, Emission 30, цвет жёлтый → красный → прозрачный, размер уменьшается. В подписи 0.6 секунды округлённо названы половиной секунды.
9. Ошибки: Single вместо Multiple, включённый Has Exit Time, выключенный Loop Time, Samples 60 для четырёх кадров.

ЛЕКЦИИ 5–6: NINE TOOLS OF SCRIPTING
1. Shooter использует cooldown 0.3, nextShot, Time.time и Instantiate. В раннем примере ввод через Input.GetKey(X).
2. Bullet получает Rigidbody2D, velocity = transform.right * 12, Destroy(gameObject, 3). Порождённые объекты должны иметь срок жизни.
3. Spawner: InvokeRepeating(nameof(Spawn), 1, 2), Random.Range(-8f, 8f), Instantiate в случайной позиции. Bomb: Invoke(nameof(Explode), 2), затем Destroy. CancelInvoke отменяет отложенные вызовы.
4. Coroutine: IEnumerator, StartCoroutine, yield return new WaitForSeconds(0.2), десять переключений sr.enabled. invincible защищает от повторного урона, в конце видимость восстанавливается.
5. Health: hp, TakeDamage(int), проверка invincible, уменьшение HP, запуск неуязвимости, GameOver при hp <= 0, Heal(int). Вызов чужого метода через GetComponent<Health>().TakeDamage(1).
6. Hazard с protected virtual OnHitPlayer. Rock наследует стандартный урон, BombHazard override наносит 2, Heart override вызывает Heal(1). virtual/override/base, двоеточие для наследования, sealed.
7. SceneManager.LoadScene(SceneManager.GetActiveScene().name) перезагружает сцену и её обычное состояние.
8. Таймер: t += Time.deltaTime, после 60 секунд gateAnimator.SetBool("Open", true). В браузерной демонстрации выживание сокращено до 20 секунд.
9. AudioSource кэшируется, короткие эффекты через PlayOneShot. Play On Awake выключен. Источники: jfxr, Kenney CC0, Freesound с проверкой лицензии.

ЛЕКЦИЯ 7: INPUT SYSTEM
1. Конкретные клавиши заменяются действиями. Цепочка: устройство → binding → action → OnMove/OnJump/OnFire.
2. Установка Input System, согласие на перезапуск backend, Active Input Handling Both для миграции, InputSystemUIInputModule на EventSystem.
3. Player map: Move Value/Vector2, WASD и стрелки через 2D Vector Composite, Gamepad leftStick. Jump Button: Space и buttonSouth. Fire Button: Mouse leftButton, X и buttonWest.
4. PlayerInput с Send Messages вызывает методы On + имя действия. OnMove(InputValue v) читает v.Get<Vector2>(). Физика использует сохранённый вектор.
5. On-Screen Stick эмулирует <Gamepad>/leftStick. On-Screen Button эмулирует buttonSouth/buttonWest. Одинаковые bindings работают с экраном и настоящим геймпадом.
6. Экранный стик внизу слева, кнопки справа. Movement Range 80. Canvas 1920×1080, Match 0.5 в этой ранней лекции.
7. Критерий миграции: нет Input.Get… в игровом коде. Эти старые вызовы остаются в ранних учебных примерах лекции 5–6, но не являются целью после миграции.

ЛЕКЦИИ 8–9: MOBILE UI AND PRE-PRODUCTION
1. Canvas Scaler Scale With Screen Size. Для landscape 1920×1080, Match 1 по высоте. Для portrait 1080×1920, Match 0 по ширине. Reference PPU 100.
2. Anchors: сердца top-left, pause top-right, stick bottom-left, действия bottom-right, окна по центру, фон stretch. Shift+Alt при выборе preset меняет также pivot и позицию.
3. SafeArea: RequireComponent RectTransform, Apply в Awake и при изменении Screen.safeArea. Позиция и верхняя граница safeArea нормализуются на Screen.width/height и назначаются anchorMin/Max.
4. Фон остаётся полноэкранным, HUD и кнопки внутри безопасной панели.
5. Touch targets минимум 48 dp Android / 44 pt iOS, примерно 9 мм или 120×120 при reference 1920×1080. Текст примерно от 36 px. Центр экрана оставляется игре.
6. Экраны: MainMenu, HUD, Pause, Win/Lose, Settings. Пауза SetActive и Time.timeScale = 0. Возврат в меню обязательно восстанавливает timeScale = 1. UI-анимации на паузе используют Unscaled Time.
7. Device Simulator: обычный экран, телефон с вырезом, планшет, поворот и Safe Area. Он не заменяет регулярную проверку настоящей сборки на телефоне.
8. Недели 9–15 развивают одну игру. Core loop описывается 3–4 повторяемыми действиями.
9. GDD: название и pitch, жанр/платформа/ориентация/2D или 3D, core loop, управление, контент, стиль/источники/звук, MVP, cut list, команда и собственная система каждого участника, недельный план.
10. Пример Barys Run вымышленный: барс, Тянь-Шань, яблоки Апорт, 3 склона, 4 опасности, 1 power-up, boss chase, дополнительная жизнь за rewarded ad. Это пример GDD, а не обязательный сюжет Skybound.
11. Git: Assets, Packages, ProjectSettings и Unity .gitignore. Исключить Library, Temp, Obj, Logs, UserSettings, Builds/APK. Visible Meta Files и Force Text. Ветка на задачу, PR и review. Один владелец сцены, использовать prefabs. Для крупных файлов Git LFS. Сообщения коммитов должны описывать изменение.

ЛЕКЦИЯ 10: ENEMY AI
1. Sense → Decide → Act. Поведение должно быть понятным, преодолимым и последовательным.
2. FSM через enum State, State state, timer, switch, SetState. В SetState сбрасывается timer, выполняются действия входа. У каждого состояния есть выход.
3. Учебный C#: Patrol/Chase/Attack. Пока игрок виден в Chase, timer = 0. Погоня заканчивается после loseTime 2. attackRange 1.2, windUp 0.5. Это каркас с методами-заглушками, не самостоятельный готовый контроллер.
4. Зрение: расстояние, угол, затем Raycast с obstacleMask. В 3D используется transform.forward и точка глаза +Vector3.up, в 2D transform.right, Vector2.Angle и Physics2D.Raycast.
5. Только Walls входят в маску. В 2D луч может попасть в собственный collider при Queries Start In Colliders.
6. Patrol: Transform[] points, MoveTowards(speed * deltaTime), порог 0.05, индекс по модулю длины массива. Точки находятся в уровне, не под врагом. С Rigidbody2D — MovePosition в FixedUpdate.
7. 3D NavMesh: AI Navigation, Surface, Bake, Agent, speed/stoppingDistance/radius. Повторный путь каждые 0.2 секунды через SetDestination. Для обычной XY 2D игры NavMesh из коробки не подходит.
8. Атака: wind-up 0.3–0.8, удар только если игрок остался в зоне, recovery примерно 0.4–1, cooldown 1–2. Игроку нужно примерно 0.25 секунды заметить и отреагировать. Прямо сказано: не атаковать из-за экрана, сначала войти в кадр, затем готовиться.
9. Patroller: маршрут, погоня, ближний удар. Пример vision 6, chase 3 при скорости игрока 4, wind-up 0.5.
10. Shooter: держит около 5 метров, прицеливается лазером, медленный снаряд. Idle/Keep distance/Aim/Cooldown, aim 0.6, projectile 5, cooldown 1.5. Стоящий на месте стрелок без лазера — адаптация, а не точное поведение демонстрации.
11. Charger: Idle/Wind-up/Dash/Stunned, trigger 6, wind-up 0.7, stun 1. В браузерной демке рывок 11 м/с до 6 метров, остановка о стену или игрока.
12. Плейтест: новый человек, телефон, без подсказок, цель 2–4 попытки. Смерти отмечаются на схеме. Менять одно число, записывать старое/новое и число попыток до/после. Приведённые числа тестов вымышлены.
13. Debug: OnDrawGizmosSelected жёлтый радиус и голубой конус. Debug.DrawRay зелёный/красный. TMP_Text 3D над врагом, SetState обновляет текст, LateUpdate поворачивает к камере. В релизе метки скрыть.
14. Не искать игрока в каждом Update. Кэшировать reference. Проверку зрения рекомендуется делать раз в 0.1–0.2 секунды. Не допускать FSM без выхода, атаки без warning и спрятанных чисел баланса.

ЛЕКЦИЯ 11: DATA AND SAVES
1. Баланс в ScriptableObject: скорость, HP, урон, дальность, задержки, количество и награды. Поведение остаётся в C#.
2. EnemyStats: CreateAssetMenu, поля public или SerializeField, Range для windUp. Asset назначается prefab. Один asset на тип.
3. Текущее hp — поле каждого экземпляра Enemy. Инициализация hp = stats.maxHP. Урон уменьшает hp, а не stats.maxHP.
4. Изменения asset в Editor Play Mode сохраняются после Stop. В билде изменения в памяти не являются сохранением игрока.
5. LevelData: enum Goal ReachExit/CollectStars/Survive, Serializable Wave(enemyPrefab/count/delay), timeLimit, goal, goalAmount, Vector2[] spawnPoints, List<Wave>. LevelLoader IEnumerator выбирает levels[GameSession.levelIndex], запускает timer, ждёт delay и создаёт врагов.
6. Значения примеров Level_01/02/03 различаются. Это данные учебного примера, а не обязательные уровни Skybound.
7. PlayerPrefs подходит для маленьких настроек, JSON для прогресса. SaveData содержит version, bestScore, List<int> unlockedLevels. Serializable поля, без свойств и Dictionary.
8. SaveSystem использует Path.Combine(Application.persistentDataPath, "save.json"), JsonUtility.ToJson(data, true), File.WriteAllText.
9. Load: File.Exists → defaults, try ReadAllText/FromJson, data ?? defaults, catch Exception → warning/defaults.
10. Безопаснее сначала записать save.tmp, затем File.Replace, для первого сохранения File.Move.
11. Сохранять после уровня, изменения настроек, OnApplicationPause(true), также можно OnApplicationFocus(false). Не полагаться на OnApplicationQuit. Не писать сохранение каждый Update.
12. Reset: игровое окно подтверждения, Cancel ничего не меняет, блокирующая Image с Raycast Target. Очистить файл, собственные PlayerPrefs keys, данные RAM и перезагрузить сцену. Не использовать DeleteAll для чужих ключей.
13. SaveSystem.Delete() и GameTimer в примерах требуют собственной реализации, это не готовые Unity API.
14. BinaryFormatter запрещён как небезопасный подход. Нельзя жёстко задавать C:/… или Assets/save.json. ScriptableObject не заменяет сохранение.

ЛЕКЦИЯ 12: GAME AUDIO
1. Звук даёт feedback, warning и ощущение действия. Сначала список событий, затем подбор звуков.
2. Один AudioListener на сцену. AudioSource: Output в нужную группу, Play On Awake off, Loop для музыки. 2D Spatial Blend 0. 3D-враги могут использовать 1.
3. PlayerSfx: AudioSource и clips jump/land/hurt, PlayOneShot. Приземление в примере тише: PlayOneShot(land, 0.6f).
4. В полной схеме лекции есть Master, Music, SFX, UI и дочерняя Music/Tracks. UI следует Master. Exposed Parameters MasterVol/MusicVol/SFXVol.
5. Слайдеры: 20 * Log10(Max(value, 0.0001)). 1 = 0 dB, 0.5 ≈ -6, 0.1 = -20, 0.0001 = -80. SetFloat в Start или позже. Сохранённую громкость применить при запуске, а не только при открытии скрытой панели.
6. PlayerPrefs достаточен для настроек, но лекция явно разрешает хранить громкость в JSON-системе недели 11.
7. Snapshots Normal и Paused. Normal стартовый. Tracks содержит Lowpass Simple. Normal 0 dB/22000 Hz, Paused -6 dB/800 Hz. TransitionTo(0.3f), mixer.updateMode UnscaledTime.
8. Отдельный Tracks нужен, поскольку SetFloat на MusicVol отдаёт этот параметр скрипту, snapshot больше не управляет им.
9. Две музыкальные дорожки: спокойная меню и более быстрая уровня. Crossfade 1 секунда через две AudioSource. Loop on, Awake off, Output Tracks. Начальный ориентир музыки -10 dB, окончательно слушать на телефоне.
10. DontDestroyOnLoad на корневом manager. Singleton в Awake уничтожает копию. Если clip тот же и isPlaying, выйти, чтобы Retry не перезапускал музыку. Coroutine использует unscaledDeltaTime, SceneMusic вызывает Play(track).
11. Повторения: Random.Range(0.92f,1.08f), 2–3 clips, не повторять последний. Альтернатива Unity 6 Audio Random Container: random/shuffle/sequential, pitch/volume randomization, Avoid Repeating Last.
12. SFX: Force To Mono On, Decompress On Load, ADPCM. Музыка: Mono Off, Streaming, Vorbis, quality подобрать на слух. WAV/OGG, проверять шов лупа пять раз. Platform overrides могут менять настройки.
13. Звуки собственного изготовления допустимы. jfxr — генератор. Kenney CC0, Freesound — отдельная лицензия каждого файла. CC BY требует автора/лицензию, CC BY-NC предлагается не брать, без лицензии не использовать. В README записывать каждый источник сразу.
14. Нельзя создавать новый AudioSource на каждый выстрел. Использовать существующий source и PlayOneShot, все sources направить в mixer. Дубликаты manager, линейные dB, музыка при Retry и одинаковый pitch — типичные ошибки.
15. В тексте аудио есть предупреждение об опасности до появления в кадре. Это отличается от правила лекции 10 о начале wind-up в кадре. Различать слышимое предупреждение и фактический удар. Не выдавать одно правило за дословное совпадение с обоими источниками.

ОБЩИЕ ПРАВИЛА ДЛЯ ДАЛЬНЕЙШЕЙ РАБОТЫ
Ранние учебные примеры развиваются: Input.Get… заменяется Input System, SerializeField баланс заменяется asset-данными, простое PlayOneShot дополняется mixer/snapshots.
Имена классов, одинаковая архитектура и совпадение каждой строки — разные уровни соответствия. Нельзя называть переработанный код дословной копией лекции.
Часть методов примеров — заглушки. Вставка без собственных компонентов GameTimer, GameSession, Strike и т.п. не создаёт готовую игру.
Лекция описывает больше деталей, чем краткий чек-лист задания. Требования конкретного Assignment нужно проверять по самому Assignment.
Пожелания пользователя остаются отдельными решениями: убрать метки/Gizmos/лазер, оставить 2D, использовать JSON для громкости. Они не становятся текстом лекции.
С недели 10 разрешены агенты, но нужен DECISIONS.md 3–5 строк за неделю и понимание собственного кода для защиты. Вымышленные примеры результатов нельзя записывать как реальные плейтесты.
При текущем запросе игровая логика не изменялась. Полная проверка соответствия текущего проекта каждой лекции — отдельная работа, а не следствие чтения.
