    2–3.  Спавнер и бомба  InvokeRepeating · Random.Range · Invoke 

    
     
 // Spawner.cs — пустой объект над сценой  
 void  Start() 
{ 
   // (метод, первый раз через, интервал)  
   InvokeRepeating (nameof(Spawn),  1f ,  2f ); 
}  
 void  Spawn() 
{ 
   float  x =  Random .Range( -8f ,  8f ); 
  Instantiate(hazardPrefab,  new   Vector3 (x,  6f , 0), Quaternion.identity); 
}
    

     
       
 // Bomb.cs — упала, тикает, взрывается  
 void  Start() 
{ 
   Invoke (nameof(Explode),  2f );  // ОДИН раз через 2 сек  
}  
 void  Explode() 
{ 
   // вспышка, звук, урон — и:  
  Destroy(gameObject); 
}
      

        Invoke vs InvokeRepeating:  один отложенный выстрел против метронома.

    4.  Корутина  IEnumerator · yield return · StartCoroutine 

    
     
 IEnumerator  Invincibility() 
{ 
  invincible =  true ; 
   for  ( int  i = 0; i < 10; i++) 
  { 
    sr.enabled = !sr.enabled;  // мигание  
     yield return new WaitForSeconds(0.2f);  
  } 
  sr.enabled =  true ; 
  invincible =  false ; 
}  
 // запуск:  StartCoroutine(Invincibility());
    

     
       

       🧡🧡🧡

       TAKE DAMAGE 
       invincible = false

        Суть:  yield return — «продолжи отсюда через 0.2 сек»,
      игра НЕ останавливается. Invoke такой цикл не умеет.

    5.  Health — скрипты говорят друг с другом  GetComponent<T> 

    
     
 // Health.cs — на герое  
 public int  hp = 3;  
 public void  TakeDamage( int  dmg) 
{ 
   if  (invincible)  return ; 
  hp -= dmg; 
  StartCoroutine(Invincibility()); 
   if  (hp <= 0) GameOver(); 
}  
 public void  Heal( int  a) { hp += a; }
    

     
       
 // у опасности: взять ЧУЖОЙ скрипт  
 // и вызвать его публичный метод  
 void  OnCollisionEnter2D( Collision2D  c) 
{ 
   if  (c.gameObject.CompareTag( "Player" )) 
    c.gameObject. GetComponent<Health>()  
      .TakeDamage(1); 
}
      

        Это главный мост Unity:  GetComponent — способ одному скрипту
      дёрнуть метод другого. До сих пор ваши скрипты жили поодиночке.

   INPUT ACTIONS .  карта смысла

    
     
 Action Map: Player  
   Move   (Value · Vector2) 
    ├ 2D Vector Composite → W / A / S / D 
    ├ 2D Vector Composite → стрелки 
    └  Left Stick [Gamepad]  ← сюда встанет экранный стик  
   Jump   (Button) 
    ├ Space [Keyboard] 
    └  Button South [Gamepad]  ← экранная кнопка JUMP  
   Fire   (Button) 
    ├ Left Button [Mouse]  ├ X [Keyboard] 
    └  Button West [Gamepad]  ← экранная кнопка FIRE 
    

     
        Value vs Button  
        Value  — значение каждый кадр: вектор движения.  Button  — событие «нажалось»: прыжок, выстрел. 

        Composite — зачем  
       W/A/S/D — 4 клавиши, не вектор. Composite склеивает их в один Vector2: W=(0,1), W+D=(0.7,0.7). Стик делает то же сам — потому они взаимозаменяемы.

  4.  Safe area: notches, holes and rounded corners

 
   
     Modern phones lose parts of the screen to a notch, a camera hole, rounded corners and the home bar.
     Screen.safeArea  is the rectangle that is really visible. Put all HUD inside one panel that follows it.

     Background art stays full screen. Only buttons and text go inside the safe panel.

     Hierarchy:  Canvas  →  Background  (stretch) +  SafeArea  (this script) → your HUD.

  

  using  UnityEngine;

[RequireComponent( typeof (RectTransform))]
 public class  SafeArea : MonoBehaviour
{
    RectTransform panel;
    Rect last;

     void  Awake() { panel = GetComponent<RectTransform>(); Apply(); }
     void  Update() {  if  (Screen.safeArea != last) Apply(); }

     void  Apply()
    {
        last = Screen.safeArea;
        Vector2 min = last.position;
        Vector2 max = last.position + last.size;
        min.x /= Screen.width;  min.y /= Screen.height;
        max.x /= Screen.width;  max.y /= Screen.height;
        panel.anchorMin = min;    // the panel's corners follow 
        panel.anchorMax = max;    // the visible part of the screen 
    }
}

  1.  What enemy AI is

 Enemy AI in a mobile game is a small set of rules that picks one behaviour at a time: walk the route, chase, aim, hit.
Simple rules are enough. The player must be able to  read it  and  beat it .

 
    1 · Sense
 What does the enemy know this frame? Distance to the player, the angle, walls in between.


    2 · Decide
 Which state is it in, and does a rule say "switch now"? That is the state machine.


    3 · Act
 Move, turn, aim or attack. Next frame it starts again at Sense.




 
    Readable:  every state looks different. The demo uses a text label; your game uses animation, color and sound.

    Beatable:  every attack has a warning before it and a gap after it.

    Consistent:  the same situation gives the same reaction. Players can learn rules. They cannot learn dice.

 

  2.  Finite state machine

 A finite state machine (FSM) is a list of  states  plus  transitions  between them.
The enemy is in exactly one state. Every frame it runs that state's code and checks the  conditions  on its arrows.

  
       
    
    sees player 
    not seen 2 s 
    closer than 1.2 m 
    strike + 0.4 s rest 
    Patrol 
    Chase 
    Attack 
 

  enum  State { Patrol, Chase, Attack }
State state;   float  timer;                  // timer = seconds in the current state 
[SerializeField]  float  attackRange = 1.2f, loseTime = 2f, windUp = 0.5f;
 void  Update()
{
    timer += Time.deltaTime;
     switch  (state)
    {
         case  State.Patrol:
            Patrol();
             if  (CanSeePlayer()) SetState(State.Chase);
             break ;
         case  State.Chase:
             if  (CanSeePlayer()) timer = 0f;    // here timer = time since last seen 
            MoveTo(player.position);
             if  (DistanceToPlayer() < attackRange) SetState(State.Attack);
             else if  (timer > loseTime) SetState(State.Patrol);
             break ;
         case  State.Attack:                   // stands still: this is the warning 
             if  (timer >= windUp) { Strike(); SetState(State.Chase); }
             break ;
    }
}

 void  SetState(State next) { state = next; timer = 0f; }    // enter logic lives here 

 
    One enum value per state.   State state;  starts as  Patrol , the first value of the enum.

    Change state only in  SetState .  It resets the timer, so "0.5 s in Attack" counts from the moment of entry. Animation triggers, sounds and the debug label go there too.

    Every state needs a way out:  a condition or a timer. A state with no exit is a frozen enemy.

 

  3.  Seeing the player

 The enemy sees the player only when three checks pass, in this order. The cheap checks go first, so most frames stop before the raycast.

 
    1 · Distance

     
       
       
         
       4 m ✓  8 m ✗ 
     
      toPlayer.magnitude > viewRange  → not seen. One subtraction, almost free.


    2 · Angle

     
       
        
        
       ✓  ✗ behind  fov 90° 
     
      Vector3.Angle(transform.forward, toPlayer) < fov / 2 . A 90° cone means 45° to each side.


    3 · Walls

     
       
         
       
        
       wall on the ray ✗ 
     
      Physics.Raycast  toward the player with a Walls mask. Any hit means blocked. The most expensive check, so it runs last.




 [SerializeField] Transform player;
[SerializeField]  float  viewRange = 6f, fov = 90f;
[SerializeField] LayerMask obstacleMask;               // tick only the Walls layer 

 bool  CanSeePlayer()
{
    Vector3 eye = transform.position + Vector3.up;       // 1 m above the feet 
    Vector3 toPlayer = player.position + Vector3.up - eye;

     // 1. distance 
     if  (toPlayer.magnitude > viewRange)  return false ;
     // 2. angle: inside the cone? 
     if  (Vector3.Angle(transform.forward, toPlayer) > fov / 2f)  return false ;
     // 3. walls: does the ray hit anything on obstacleMask before the player? 
     if  (Physics.Raycast(eye, toPlayer.normalized,  out  RaycastHit hit,
                        toPlayer.magnitude, obstacleMask))
         return false ;                                   // hit.collider is the wall 

     return true ;
}

  // 2D game: the same three checks with Vector2 and Physics2D 
Vector2 toPlayer = player.position - transform.position;
 if  (toPlayer.magnitude > viewRange)  return false ;
 if  (Vector2.Angle(transform.right, toPlayer) > fov / 2f)  return false ;    // sprite that faces right 
RaycastHit2D hit = Physics2D.Raycast(transform.position, toPlayer.normalized, toPlayer.magnitude, obstacleMask);
 return  hit.collider ==  null ;

  LayerMask:  put every wall on a  Walls  layer and tick only Walls in  obstacleMask .
Now the ray ignores the enemy's own collider, other enemies and the player. In 2D this matters most: a ray that starts inside the enemy's own collider can hit it
(Physics 2D setting  Queries Start In Colliders ), and the enemy never sees anyone.


  4.  Moving

 2D: walk between waypoints you place by hand. 3D: bake a NavMesh and let the agent find a path around the walls.

 
   
     2D · waypoints

     Place empty GameObjects along the route and drag them into the array. They must sit in the level, not inside the enemy, or they move with it.

 [SerializeField] Transform[] points;
[SerializeField]  float  speed = 1.7f;            // m/s 
 int  i;

 void  Patrol()
{
    Vector2 target = points[i].position;
    transform.position = Vector2.MoveTowards(
        transform.position, target, speed * Time.deltaTime);
     if  (Vector2.Distance(transform.position, target) < 0.05f)
        i = (i + 1) % points.Length;           // next point, loop to 0 
}

     If the enemy has a Rigidbody2D, move it with  rb.MovePosition(...)  in  FixedUpdate  instead of setting  transform.position .

  

   
     3D · NavMesh (AI Navigation package)

     
       Install  AI Navigation  in the Package Manager if the project does not have it.

       Select the floor →  Add Component → Navigation → NavMesh Surface  → click  Bake . A blue overlay in the Scene view marks where agents can walk.

       Enemy →  Add Component → Navigation → NavMesh Agent . Set Speed, Stopping Distance and Radius.

       Moved a wall? Click  Bake  again.

     
  



  using  UnityEngine;
 using  UnityEngine.AI;

[RequireComponent( typeof (NavMeshAgent))]
 public class  ChaseMover : MonoBehaviour
{
    [SerializeField] Transform target;
    [SerializeField]  float  chaseSpeed = 3f, attackRange = 1.2f;    // player runs at 4 m/s 
    NavMeshAgent agent;
     float  repath;                                    // seconds until the next path 
     void  Awake()
    {
        agent = GetComponent<NavMeshAgent>();
        agent.speed = chaseSpeed;
        agent.stoppingDistance = attackRange;           // stop where the attack starts 
    }

     void  Update()
    {
        repath -= Time.deltaTime;
         if  (repath > 0f)  return ;
        repath = 0.2f;                                  // a new path 5 times per second 
        agent.SetDestination(target.position);
    }
}

  2D games:  the built-in NavMesh is baked from 3D geometry. A 2D game on the XY plane gets no NavMesh out of the box. Use waypoints, or a grid of walkable cells.


  5.  Fair attacks

 A fair attack has three parts: a  warning , the  strike , and a  gap  where the player can hit back.
Players accept a hit they saw coming. They quit after a hit they could not see.

  
   WIND-UP 0.3–0.8 s 
   STRIKE 
   RECOVERY 
   
   
   
   
   
   cooldown 1–2 s 
   color + animation + sound 
   enemy stands still: hit back 
   
   ≈ 0.25 s: the player notices and reacts 
   
   
   0  0.5 s 
   1.0 s  1.5 s 
 

 
    Wind-up 0.3–0.8 s.  Change color, play a wind-up animation and a sound. A player needs roughly 0.25 s just to notice and react, so anything shorter feels like a cheap shot.

    The strike only hits if the player is still in reach.  Moving away during the wind-up must work.

    Always leave a counter window.  After the strike the enemy stands still or is stunned for 0.4–1 s. That is the player's turn.

    Never attack from off-screen.  An enemy outside the camera view walks into view first, then winds up.

    Cooldown 1–2 s  before the same enemy attacks again.

    Typical agent mistake  What you do 

     GameObject.Find("Player")  or  FindObjectOfType  inside  Update , and a sight raycast every frame for every enemy  Get the player once: a  [SerializeField]  reference, or  FindFirstObjectByType  in  Awake .  FindObjectOfType  is obsolete in Unity 6. Check sight every 0.1–0.2 s with a timer. 

    Raycast without a LayerMask: the ray hits the enemy's own collider or another enemy  Walls layer +  obstacleMask  with only Walls ticked. 

    States with no exit, or the timer never reset: stuck in Chase forever, Attack fires every frame  Every state has a condition or a timer out. Change state only through  SetState , which resets the timer. 

    Attack with no wind-up: damage on the same frame the player comes close  Add a 0.3–0.8 s wind-up with color + sound, then a recovery gap. 

    Magic numbers:  if (d < 1.2f)  buried in the code   [SerializeField]  fields with units in a comment. Tune them in the Inspector during the playtest.

    if (Physics.Raycast(eye, toPlayer.normalized, out RaycastHit hit,
                        toPlayer.magnitude, obstacleMask))
        return false;                                  // hit.collider is the wall

    return true;
}

  Part A  Game data · ScriptableObjects


  1.  Magic numbers

 A magic number is a value typed straight into code:  speed = 3.5f . One enemy speed easily ends up in six scripts.
To make enemies 20% faster, someone has to find all six, change them, recompile and hope none was missed.

 
   
     Where speed lives 
     
       6 scripts, 6 numbers 
       1 EnemyStats asset 
    

     Designer asks 
     
       Make enemies 20% faster 
       Reset 
    

  

   

   



 
    Designers do not edit C#.  Balancing means 30–50 small tries. If every try needs a programmer and a recompile, nobody tries.

    You cannot compare.  Level 1 numbers and level 3 numbers sit in different files, so the difficulty curve is invisible.

    Rule for Assignment 11:  no balance number lives in a script. Speed, HP, damage, timers, counts and rewards go into data assets.

 

  2.  ScriptableObject: a data asset

 A ScriptableObject is a data asset: a file in the Project window, like a material or a prefab.
You fill in its numbers in the Inspector. Scripts read them.

  using  UnityEngine;

     public float  speed = 2.5f;         // units per second

     public float  visionRange = 4f;    // units

      One asset per enemy type:   Slime_Stats ,  Bat_Stats ,  Boss_Stats . Same script, different numbers.

      Connect it:  drag the asset into the  Stats  field of the enemy prefab.

  A ScriptableObject is not a save system.  In the Editor, values you change on the asset in Play Mode stay in it after you press Stop.
That is handy for tuning: commit the asset to Git. In a build, runtime changes live only in memory, and every launch starts again from the values you shipped.
The player's progress goes into a save file (Part B).

  4.  Saving: PlayerPrefs vs a JSON file

 Game data ships inside the build. Player data is born on the phone: best score, unlocked levels, volume.
Unity gives you two simple places to keep it. Use both, each for its own job.

  5.  Loading safely

 On a real phone the save file can be missing (first launch, after a reset) or broken (the battery died while the game was writing).
Load has to survive both and still start the game.

 
  public static  SaveData Load()
{
     if  (!File.Exists(FilePath))  return new  SaveData();

     try 
    {
         string  json = File.ReadAllText(FilePath);
         var  data = JsonUtility.FromJson<SaveData>(json);
         return  data ??  new  SaveData();  // empty → null 
    }
     catch  (System.Exception e)
    {
        Debug.LogWarning("Broken save: " + e.Message);
         return new  SaveData();
    }
}

   
      Missing file:   File.Exists  is false on the first launch and after a reset. Return defaults.

      Broken file:   FromJson  throws an exception.  catch  returns defaults, and the game still starts.

      Empty file:   FromJson  returns  null  for empty text.  ??  turns it into defaults.

      Log it:   Debug.LogWarning  shows in the Console and in Android Logcat, so you find out.

   


  Safer writing:  write the new save into  save.tmp  first, then replace the old file.
If the battery dies during step 1, only  save.tmp  is broken.  save.json  still holds the last good save.

  public static void  Save(SaveData data)
{
     string  tmp = Path.Combine(Application.persistentDataPath, "save.tmp");
    File.WriteAllText(tmp, JsonUtility.ToJson(data,  true ));   // 1. write a full new copy 

     if  (File.Exists(FilePath))
        File.Replace(tmp, FilePath,  null );   // 2. swap it in, no backup file 
     else 
        File.Move(tmp, FilePath);           // very first save 
}

  6.  When to save on mobile

 Phones do not close apps politely. The player presses Home, takes a call or switches apps.
Later the OS kills the app in the background to free memory, and your code gets no warning. Save at the moments when you still have control.

  
   
   
   
      ✓ 
      ✓ 
      ✓ 
     
      ✗ 
     
       Level complete  Volume changed  Home button, call 
       In background  OS kills the app 
     
     
       SaveSystem.Save()  PlayerPrefs.Save() 
       OnApplicationPause(true)  → SaveSystem.Save() 
       your code is frozen  no callback at all 
     
   
 

 
  public class  SaveManager : MonoBehaviour
{
     public  SaveData Data {  get ;  private set ; }

     void  Awake() { Data = SaveSystem.Load(); }

     public void  LevelCompleted( int  level,  int  score)
    {
        Data.bestScore = Mathf.Max(Data.bestScore, score);
         if  (!Data.unlockedLevels.Contains(level + 1))
            Data.unlockedLevels.Add(level + 1);
        SaveSystem.Save(Data);                // moment 1 
    }

     public void  ResetToDefaults() => Data =  new  SaveData();

     void  OnApplicationPause( bool  paused)
    {
         if  (paused) SaveSystem.Save(Data);    // moment 3 
    }
}

   
      1. After a level is completed.  The win screen is a calm moment: save there.

      2. When settings change.   PlayerPrefs.Save()  when the player closes the settings panel.

      3. In  OnApplicationPause(true) .  Unity calls it when the app goes to the background. It may be the last code that ever runs.

      Do not rely on  OnApplicationQuit .  Unity's docs say it is not called when iOS suspends the app, and the OS may kill a suspended app without it. They also suggest  OnApplicationFocus(false) ; saving a small file twice does no harm.

      Never save in  Update .  That writes the file again on every single frame.

 Typical agent mistakes on this topic

 
    BinaryFormatter.  Old tutorials use it. Microsoft says it is insecure, cannot be made secure, and apps should stop using it. Use  JsonUtility .

    Dictionary or properties in SaveData.   JsonUtility  saves serializable fields only: a  Dictionary  or a  { get; set; }  property silently disappears from the file. Use a  List .

    Runtime state inside a ScriptableObject.   stats.maxHP -= damage  hurts every enemy that shares the asset, and in the Editor the change stays after Play Mode.

    No try/catch on load.  One broken file and the game never starts again until the player reinstalls it.

    Saving only in  OnApplicationQuit .  On a phone it may never run.

    Hard-coded paths.   "C:/Users/me/save.json"  or  "Assets/save.json"  work on your PC only. Use  Path.Combine(Application.persistentDataPath, "save.json") .

  1.  Why sound matters

 Mute any good mobile game and it suddenly feels broken. Sound does three jobs at once.

 
    Feedback
 Every tap, jump and pickup answers back. The player knows the action worked without looking at the HUD.


    Warning
 The enemy wind-up starts about half a second before the attack. The player reacts to an enemy that is still off-screen.


    Feel
 A light rising jump, a heavy low hit, a bright pickup. Sound gives every action its weight.




  Rule for this week:  every player action and every enemy attack has a sound.

 Start with a sound list

  
  Event  Sound  Group 

  Jump  short rising blip  SFX 

  Land  soft thud, quieter than the jump  SFX 

  Collect an apple  bright two-note chime  SFX 

  Take damage  hit + short low tone  SFX 

  Falling rock (enemy attack)  rumble that starts 0.5 s before the rock falls  SFX 

  Button tap  click  UI 

  Menu · slope  calm loop · faster loop  Music 

 

 Example: Barys Run from the week 9 GDD. Write this list for your own game before you search for a single sound.


  2.  AudioSource and AudioListener

 The  AudioListener  is the ear. An  AudioSource  is a speaker on an object.
A scene has exactly one ear and as many speakers as you need.

 
    
         
     
        Main Camera  AudioListener · the ear 
        Player  2D · PlayOneShot 
        Enemy  3D in a 3D game 
        MusicManager  2 sources · Loop 
        UI buttons  2D · click 
     
     
          
     
   

    
      AudioSource field  Use 

      Audio Resource  the clip it plays (Unity 6 name for the clip field) 

      Output  its mixer group: SFX, UI or music (section 3) 

      Play On Awake  off: your scripts decide when 

      Loop  on for music, off for effects 

      Pitch  1 = normal speed and pitch 

      Spatial Blend  0 = 2D, same volume everywhere · 1 = 3D, quieter far from the listener 

   



 
    One AudioListener per scene.  Unity puts it on the Main Camera. When you add a second camera, remove its listener.

     PlayOneShot(clip)  for short effects.  It layers: a new hit does not cut the one still ringing. One AudioSource per object is enough for all its effects.

     Play()  for music and loops.  It plays the clip in Audio Resource.

    2D game:  Spatial Blend 0 everywhere.  3D game:  enemy sources 1, so far enemies sound quieter. Player, UI and music stay 0.

 
  using  UnityEngine;

 public class  PlayerSfx : MonoBehaviour
{
     public  AudioSource sfx;           // on the player · Output = SFX · Spatial Blend 0 
     public  AudioClip jump, land, hurt;

     // call these from your player controller 
     public void  OnJump() => sfx.PlayOneShot(jump);
     public void  OnLand() => sfx.PlayOneShot(land, 0.6f);    // 60% volume 
     public void  OnHurt() => sfx.PlayOneShot(hurt);
}


  3.  AudioMixer: one knob per group

 The Audio Mixer is a set of volume knobs for groups of sounds. Your settings menu moves three of them:
 Master ,  Music  and  SFX .

 
    
         
     
        Master  MasterVol 
        Music  MusicVol 
        SFX  SFXVol 
        UI  follows Master 
        Tracks  pause effect 
     
     
          
     
     
       ↑ player, enemies 
       ↑ buttons 
       ← MusicManager's 2 sources 
       sound flows up to Master 
     
   

   
     Open the Audio Mixer window and press  +  in the Mixers panel. The new mixer already has a Master group.

     Right-click Master →  Add child group : Music, SFX, UI. Right-click Music → Add child group: Tracks.

     On every AudioSource set  Output  to its group. Prefabs too.

     Select the Music group. In the Inspector right-click  Volume  →  Expose … to script .

     Open  Exposed Parameters  (top right of the mixer window) and rename it  MusicVol . Same for Master and SFX.

   



 From slider to decibels

 A mixer fader works in decibels (dB):  0 dB  is full volume,  −80 dB  is silence. A UI slider gives 0 to 1.
The ear hears volume in ratios, so convert with  Log10 : 1 → 0 dB, 0.5 → −6 dB, 0.1 → −20 dB, 0.0001 → −80 dB.
Drag the slider and compare the two lines.

 
   
     Music slider 
     
     SetFloat gets 
     
       Log10(v) × 20 
       v × 80 − 80 (linear) 
    

  

     

   

   

   Press ▶ Start audio at the top first: this slider moves the Music fader up there, so you hear both mappings.



  using  UnityEngine;
 using  UnityEngine.Audio;
 using  UnityEngine.UI;

 public class  VolumeSlider : MonoBehaviour
{
     public  AudioMixer mixer;
     public string  param = "MusicVol";    // the exposed parameter name 
     public  Slider slider;                // Min Value 0.0001, Max Value 1 

     void  Start()                         // not Awake: SetFloat needs Start or later 
    {
        slider.value = PlayerPrefs.GetFloat(param, 0.8f);
        slider.onValueChanged.AddListener(Set);
        Set(slider.value);
    }

     void  Set( float  value)
    {
        mixer.SetFloat(param, Mathf.Log10(Mathf.Max(value, 0.0001f)) * 20f);
        PlayerPrefs.SetFloat(param, value);    // remembered on the next launch 
    }
}

 
    Why 0.0001?   Log10(0)  is minus infinity.  Mathf.Max  keeps the value at 0.0001, which is exactly −80 dB.

    Save it.  PlayerPrefs is enough for three numbers. If your week 11 save system has a settings part, keep the volumes there instead.

    Apply at launch.  A hidden settings panel runs  Start  only when it opens. Apply the saved volumes once when the game starts too, for example in the MusicManager.

 

  4.  Snapshots: the pause sound

 A snapshot saves the state of the whole mixer. Switch to another snapshot and Unity slides every value to it.
Classic use: in the pause menu the music goes muffled and quieter, as if it plays behind a door. Try  Pause → Paused  in the mixer at the top.

 
   
     In the Snapshots panel press  +  and name it  Paused . Name the first snapshot  Normal , right-click it →  Set as Start Snapshot .

     Select the Tracks group, press  Add..  at the bottom of its strip, pick  Lowpass Simple . It cuts the high sounds above its Cutoff freq.

     Select each snapshot and set Tracks to the values in the table.

   
    
      Tracks group  Normal  Paused 

      Volume  0 dB  −6 dB 

      Lowpass Simple · Cutoff freq  22000 Hz  800 Hz 

   



  using  UnityEngine;
 using  UnityEngine.Audio;

 public class  PauseAudio : MonoBehaviour
{
     public  AudioMixer mixer;
     public  AudioMixerSnapshot normalSnapshot, pausedSnapshot;

     void  Start()
    {
         // pause sets Time.timeScale = 0: let snapshot transitions run on real time 
        mixer.updateMode = AudioMixerUpdateMode.UnscaledTime;
    }

     // call it from your SetPaused(bool) of week 8 
     public void  SetPaused( bool  isPaused)
    {
         if  (isPaused) pausedSnapshot.TransitionTo(0.3f);    // 0.3 s slide 
         else  normalSnapshot.TransitionTo(0.3f);
    }
}

  Why a separate Tracks group?  After  SetFloat("MusicVol", …)  snapshots can no longer move the Music volume: the script owns it.
So the settings slider lives on Music, and the pause effect lives on its child Tracks.

 A mixer in Normal update mode follows scaled game time. With  Time.timeScale = 0  the transition would stall, so the script sets Unscaled Time.


  5.  Music: two tracks and a crossfade

 Two tracks: a calm one for the menu, a faster one for the level. Switch with a  1 s crossfade :
the new track fades in while the old one fades out. Try  Crossfade to Level  at the top.

 
    
      
      1  0 
     0 s  0.5 s  1 s 
     time  volume  
     
     
     Menu fades out 
     Level fades in 
   

   
      Seamless loop:  the end of the file flows into its start. Cut it on a bar line, no silence at either end. Listen to the seam 5 times.

      Import WAV or OGG.  MP3 files often start with a few milliseconds of silence, which you hear as a gap at every loop.

      Two AudioSources  on the manager: Loop on, Play On Awake off, Output = Tracks.

      Music sits under the effects.  Start with the Music group at −10 dB and adjust on the phone speaker.

   


 The manager survives scene loads with  DontDestroyOnLoad . When a scene that contains another copy loads again, the copy destroys itself.

  using  System.Collections;
 using  UnityEngine;

 public class  MusicManager : MonoBehaviour
{
     public static  MusicManager Instance;
     public  AudioSource a, b;    // Loop on · Play On Awake off · Output = Tracks 
    AudioSource current;

     void  Awake()
    {
         if  (Instance !=  null ) { Destroy(gameObject);  return ; }    // the copy from a reloaded scene 
        Instance =  this ; current = a;
        DontDestroyOnLoad(gameObject);    // works on a root object only 
    }

     public void  Play(AudioClip clip,  float  fade = 1f)
    {
         if  (current.clip == clip && current.isPlaying)  return ;    // same track keeps playing 
        AudioSource next = current == a ? b : a;
        next.clip = clip; next.volume = 0f; next.Play();
        StopAllCoroutines(); StartCoroutine(Crossfade(current, next, fade));
        current = next;
    }

      // MusicManager, continued 
    IEnumerator Crossfade(AudioSource from, AudioSource to,  float  time)
    {
         for  ( float  t = 0f; t < 1f; t += Time.unscaledDeltaTime / time)
        {
            from.volume = 1f - t;
            to.volume = t;
             yield return null ;
        }
        from.Stop(); to.volume = 1f;
    }
}

 // SceneMusic.cs · one per scene: the menu gets the menu track, levels the level track 
 public class  SceneMusic : MonoBehaviour
{
     public  AudioClip track;
     void  Start() => MusicManager.Instance.Play(track);
}

 Retry reloads the level: the second manager destroys itself in Awake, and  Play  returns early because the same clip is already playing. The music never restarts.


  6.  Variation: no machine gun

 The same hit at the same pitch five times in a row sounds like a machine gun: the ear catches the exact repeat.
Two small changes fix it:  random pitch 0.92–1.08  (±8%) and  2–3 versions  of each sound.
Press  Hit ×5  at the top with Variation Off, then with Pitch + 3 clips.

  using  UnityEngine;

 public class  SfxPlayer : MonoBehaviour
{
     public  AudioSource source;    // one per object · Output = SFX 
     public  AudioClip[] hits;      // 2–3 versions of the same hit 
     int  last = -1;

     public void  PlayHit()
    {
         int  i = Random.Range(0, hits.Length);                      // int version: max is excluded 
         if  (i == last && hits.Length > 1) i = (i + 1) % hits.Length;    // never the same clip twice 
        last = i;
        source.pitch = Random.Range(0.92f, 1.08f);                 // ±8% 
        source.PlayOneShot(hits[i]);
    }
}

 Same result without code: Unity 6 has the  Audio Random Container  asset. It holds a list of clips with Playback Mode (Sequential, Shuffle, Random),
Volume and Pitch randomization and Avoid Repeating Last. Put it in the AudioSource's Audio Resource; with Trigger set to Manual each  Play()  picks a clip.


  7.  Mobile import settings

 Click a clip in the Project window and its import settings open in the Inspector. Phones have little memory,
so short effects and long music get different settings. The Inspector shows the file size, check it after each change.

  
  Setting  Short SFX: jump, hit, pickup  Music: menu, level 

  Force To Mono  On  Off (keep stereo) 

  Load Type  Decompress On Load  Streaming 

  Compression Format  ADPCM  Vorbis 

  Quality  not used by ADPCM  lower it step by step until you hear a loss, then raise it a little 

  Why  ready at once, plays many times. Unity suggests ADPCM for noisy repeated sounds like impacts and footsteps.  read from disk while it plays, minimal memory. Each streaming clip costs about 200 KB. 

 

 Select all your SFX clips at once to change them together. Platform tabs (Android, iOS) can override the Default tab.

  9.  Working with an agent

 AI chats and AI agents (Claude Code, Codex, Cursor) are allowed. You lead, the agent helps.
Audio code is short, so agents write it fast and wrong in quiet ways: it compiles and still sounds bad. Listen after every change.

 
    Let the agent scaffold

   
     The MusicManager: one instance, two sources, crossfade coroutine.

     The VolumeSlider: Log10 conversion, PlayerPrefs.

     An SfxPlayer with clip arrays and random pitch.

     A list of every AudioSource in your scenes and prefabs with its Output group.

   

    You decide

   
     The sound list: which event gets which sound, how each enemy warns before it attacks.

     The mix: how loud music sits under the effects. Judge it on the phone speaker.

     The two tracks and the moment the music changes.

     Every source and its license in the README.

   



 Typical agent mistakes

  
  Mistake  What you notice  Fix 

  Linear volume on the mixer:  SetFloat("MusicVol", value)  or  value * 80 - 80   the slider does nothing, or its whole bottom half sounds silent   Mathf.Log10(Mathf.Max(value, 0.0001f)) * 20f  

  AudioSources not routed to mixer groups  the SFX slider leaves some sounds at full volume  set Output on every AudioSource and prefab 

  A new AudioSource for every shot:  AddComponent<AudioSource>()  or  AudioSource.PlayClipAtPoint   objects pile up in the Hierarchy, the sounds skip your mixer  one AudioSource per object +  PlayOneShot  

  Two music managers after a scene reload  two tracks on top of each other after Retry  Instance check in Awake,  DontDestroyOnLoad  on a root object 

  Music restarted on every level load  the level track jumps back to its start on every Retry  return early when the same clip is already playing 

  All sounds at the same pitch  machine-gun hits and footsteps  pitch 0.92–1.08 and 2–3 clips per action 

 

  Decision log: two example lines

 
   1. Asked Claude Code for a music volume slider. It passed the 0–1 value straight to SetFloat, so the slider did nothing. Changed it to Log10 × 20 with Min Value 0.0001; now 0.5 gives −6 dB.

   2. The agent's MusicManager had no duplicate check: after Retry two level tracks played. Added the Instance check in Awake and the same-clip check in Play.




  Every assignment has a decision log  of 3–5 lines: what you asked the agent, what it got wrong, what you changed and why.
At the end-of-term defense you explain any part of your code. Cannot explain → 0.
